# layout — автоматическая вёрстка макетов

Слушает `ai.draft_generated`, собирает печатный PDF по шаблону продукта и превью каждой страницы,
кладёт их в media и публикует `layout.generated`. Этап «дизайнер верстает» идёт без человека.

```
ai.draft_generated ─▶ GET projects /internal/projects/:id/layout-source  (ответы, вклады, версия)
                     ─▶ GET catalog /products/:id                        (подписи полей, форматы)
                     ─▶ media /files/<фото>  → размеры, EXIF-ориентация, превью-миниатюры (кэш в media)
                     ─▶ шаблон продукта → модель документа (что где на каждой странице, в пунктах)
                     ─▶ PDF (pdfkit, поток в файл) + SVG-превью страниц → PUT media /internal/files/*
                     ─▶ layout.generated { projectId, version, pdfUrl, pages[].previewUrl, warnings }
```

После пяти неудачных попыток публикуется `layout.failed`, и projects передаёт заказ человеку.
Сервис без БД и без состояния: повторная доставка события даёт ту же версию, projects принимает её один раз.

## Шаблоны (`src/templates/`)

| Продукт | Шаблон | Что выходит |
|---|---|---|
| Cover Me | `glossy-magazine@3` | A4, ровно 24 или 36 страниц в одном из четырёх стилей (`src/templates/glossy-themes.ts`): «Глянец», «Таблоид», «Нежность», «Нуар» — свои палитра, шрифты, подача рубрик и композиция обложки. В «Глянце» и «Нежности» акцент берётся из самого яркого цвета фото обложки. Рубрики: обложка, содержание, письмо редактора, досье, интервью, вкусы, хронология, «В цифрах», гороскоп, «Тогда и сейчас», правила жизни, друзья, «Одним словом», очерк, фотосессия с цитатами, пожелания гостей, задняя обложка. Заголовки рубрик, строку на обложке и гороскоп пишет ИИ (`draft.art`); без ИИ шаблон подставляет свои, тоже персональные |
| Шежіре | `shezhire-book@1` | A4, 48 или 64 страницы: обложка с орнаментом, посвящение, вступительное слово, содержание, древо по поколениям (по отцу слева, по матери справа), главы летописи, главы по поколениям с биографиями и фото, семейные истории, воспоминания родных, архив (фото не обрезаются), страницы для потомков |
| MyGame | `boardgame-kit@1` | Крышка коробки, правила, карты персонажей и колода 63×88 мм по 9 на лист A4 с метками реза, рубашки после каждого листа (зеркально, для двусторонней печати), поле 40×40 или 50×50 см, банкноты с лицами игроков для «Своей экономической» |

Шаблон читает ответы по id полей из `services/catalog/src/products/*`, но переживает переименование вопроса:
пустой ответ просто не печатается. Если материалов больше формата, текст уменьшается (до 87%), и только потом
книга растёт кратно 4 страницам с предупреждением для студии. Предупреждения (пропущенные HEIC, нехватка мест на поле,
пустые страницы) видны в `/admin` у версии макета.

Посмотреть шаблоны глазами: `npm run sample -- /tmp/px-samples` — PDF и SVG всех трёх продуктов на тестовых данных.

## Почему pdfkit, а не Chromium

Сервер общий, памяти мало, а релиз собирается без нативных модулей (`deploy/build-release.sh` отклоняет `*.node`).

| Вариант | Память | Минусы |
|---|---|---|
| HTML + Paged.js в headless Chromium (Puppeteer) | процесс браузера ~150–300 МБ на старте и растёт с картинками; +170 МБ на диске | второй тяжёлый рантайм рядом с MyBooks и DoseWear, бинарник под платформу сервера, долгий холодный старт |
| React-PDF | pdfkit внутри + React и движок раскладки yoga | та же основа, но лишний слой; шрифты и картинки так же целиком в памяти |
| pdf-lib | держит весь документ в памяти и при `save()` собирает его одним буфером | с 40–70 фото с телефона это сотни мегабайт |
| **pdfkit + своя раскладка (выбрано)** | пишет PDF потоком в файл, фото встраивает как есть (без перекодирования) и сразу отпускает | раскладку текста пишем сами (`src/domain/text.ts`): переносы по словам, выключка, подбор кегля, подмена глифов |

Своя раскладка даёт одну модель документа на два рендера: PDF для типографии и SVG-превью для кабинета.
Позиции считаются один раз, поэтому превью совпадает с печатью. В SVG текст сохранён контурами (шрифты не нужны),
фото вставлены миниатюрами: страница открывается в обычном `<img>` без внешних запросов.

Миниатюры без нативных модулей: большой JPEG декодируется в 1/8 масштаба только по DC-коэффициентам
(`src/infrastructure/jpeg-dc.ts`). Это точное среднее каждого блока 8×8, без обратного DCT и без полноразмерного
растра. Полное декодирование чистым JS (jpeg-js) съедало ~480 МБ на одно фото 12 Мп; DC-декодер — единицы мегабайт и в 3 раза быстрее.

### Замеры

`npm run bench -- 40 12`: Cover Me на 36 страниц, фото 4000×3000 по 4,6 МБ, собранный бандл, Node 22, MacBook.

| Фото | Время | PDF | Превью (все страницы) | Пик RSS процесса |
|---|---|---|---|---|
| 40 × 12 Мп | 7,4 с | 184 МБ | 1 МБ | 274 МБ |
| 70 × 12 Мп | 13 с | 321 МБ | 1,3 МБ | 268 МБ |

Пик не растёт с числом фото: они обрабатываются по одному, PDF уходит на диск с учётом backpressure.
До DC-декодера и backpressure тот же прогон занимал 22 с и 650 МБ. Около 130 МБ из пика — сам процесс с загруженными
модулями и шрифтами. Для PM2 сервису стоит дать `max_memory_restart: 400M`; одновременно верстается один заказ на реплику.

## Шрифты

Те же гарнитуры, что на сайтах брендов (SIL OFL): Playfair Display + Inter Tight, Cormorant Garamond + Literata,
Unbounded + Rubik. Сборка копирует файлы в `dist/fonts`. В Unbounded нет казахских букв: недостающие глифы
подставляются из Rubik, в Playfair — из Literata (подмена по каждому символу).

## Запуск

```bash
cp .env.example .env
npm run dev
npm test          # раскладка, шаблоны, изображения, весь цикл события на шине в памяти
```

`POST /internal/preview` с `{ source, draft }` (схема `LayoutPreviewRequest`) возвращает PDF, ничего не сохраняя:
удобно для настройки шаблонов.
